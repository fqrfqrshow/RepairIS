# Демонстрация транзакций и уровней изоляции (адаптация под JSON)

## 1. Демонстрация принципа «всё или ничего» (Atomicity)

### Сценарий 1. Успешное сохранение заявки (аналог COMMIT)
1. Пользователь заполняет форму создания заявки.
2. Данные сериализуются в `orders.tmp.json`.
3. Проверка успешна — файл переименовывается в `orders.json`.
4. Заявка сохранена.

**Результат:** данные записаны полностью.

### Сценарий 2. Отказ при ошибке (аналог ROLLBACK)
1. Пользователь пытается сохранить заявку с `clientId = null`.
2. Приложение выбрасывает `ArgumentNullException`.
3. Запись в `orders.tmp.json` прерывается.
4. `orders.json` остаётся нетронутым.

**Результат:** данные не записаны, база в исходном состоянии.

### Сценарий 3. Проверка ограничения
1. Пользователь пытается сохранить заявку со статусом `Unknown`.
2. Валидация в коде отклоняет значение (статус должен быть из списка).
3. Сохранение не происходит.

**Результат:** ограничение целостности защищает данные.

## 2. Уровни изоляции

В JSON-хранилище нет встроенных уровней изоляции. Однако в коде реализована блокировка файлов:
1. При чтении файла используется `FileShare.Read` — другие процессы могут читать, но не писать.
2. При записи — `FileShare.None` — файл заблокирован на время записи.

Это предотвращает повреждение данных при параллельном доступе.

## 3. Вывод

JSON-хранилище не поддерживает транзакции ACID в полном смысле. Однако принцип «всё или ничего» реализуется через паттерн безопасной записи (временный файл + атомарное переименование), что обеспечивает надёжность данных.

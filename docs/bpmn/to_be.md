# To-Be: целевой процесс обработки заявок с RepairIS

## Участники процесса
- Заказчик
- Менеджер
- Мастер
- **Система RepairIS** (новая роль — автоматизация)

## Пошаговое описание процесса

### Шаг 1. Создание заявки
Заказчик авторизуется в RepairIS и заполняет форму создания заявки:
- выбирает станок из списка (или добавляет новый)
- вводит описание неисправности
- выбирает способ осмотра (выезд / самостоятельный приезд)
- указывает контактные данные

Система автоматически:
- присваивает Id заявки
- ставит дату создания
- присваивает статус «Ожидает обработки»
- сохраняет в orders.json

### Шаг 2. Обработка менеджером
Менеджер видит заявку в разделе «Все заявки».
Фильтрует по статусу «Ожидает обработки».
Открывает карточку, проверяет данные.

Если данные корректны — принимает заявку → статус «Принята в работу».
Если нет — возвращает заказчику с комментарием.

### Шаг 3. Назначение мастера
Менеджер в форме управления заявкой выбирает мастера из списка.
Система:
- фиксирует назначение
- меняет статус на «Назначен мастер»
- сохраняет в orders.json

Мастер видит назначенную заявку в своём личном списке.

### Шаг 4. Осмотр
Мастер открывает заявку, вносит результаты осмотра в форму:
- описание неисправности
- необходимые детали
- трудоёмкость (в часах)
- ориентировочная стоимость

Система сохраняет осмотр в inspections.json.

### Шаг 5. Формирование сметы
Менеджер на основе данных осмотра формирует смету в форме:
- работы
- детали
- логистика
- дополнительные расходы

Система автоматически:
- считает итоговую сумму
- считает НДС
- сохраняет в estimates.json
- отправляет заказчику на согласование

### Шаг 6. Согласование сметы
Заказчик открывает смету в системе.
Нажимает «Подтвердить» или «Отклонить».

Система:
- фиксирует решение
- меняет статус заявки
- уведомляет менеджера

### Шаг 7. Ремонт
Мастер нажимает «Начать ремонт» → статус «В процессе».
По завершении нажимает «Завершить ремонт», вводит:
- дату окончания
- описание выполненных работ

Система:
- сохраняет данные
- меняет статус на «Завершено»
- уведомляет менеджера и заказчика

### Шаг 8. Оплата и закрытие
Менеджер отмечает оплату → статус «Оплачено».
Заявка закрывается.

## Точки автоматизации

| № | Шаг процесса | Что делает система вместо человека |
|---|---|---|
| 1 | Создание заявки | Форма вместо звонка; автогенерация Id и даты; запись в JSON |
| 2 | Обработка заявки | Фильтрация по статусу; сохранение изменений статуса |
| 3 | Назначение мастера | Список мастеров; автоматическое уведомление; запись в JSON |
| 4 | Осмотр | Форма вместо бумаги; сохранение в inspections.json |
| 5 | Смета | Автоматический расчёт суммы и НДС; сохранение в estimates.json |
| 6 | Согласование | Электронное подтверждение; смена статуса автоматически |
| 7 | Ремонт | Смена статусов кнопками; фиксация дат и описания |
| 8 | Оплата | Фиксация оплаты; автоматическое закрытие заявки |

## Эффект от внедрения

- Заявки не теряются — всё хранится в JSON.
- История по станку и клиенту доступна в один клик.
- Статус заявки прозрачен для всех ролей.
- Смета рассчитывается автоматически — исключены ошибки.
- Отчёты формируются по запросу менеджера.
- Сокращение времени обработки заявки с 1–2 дней до нескольких часов.

# ADR-001. Выбор архитектурного стиля

## Статус
Принято

## Дата
2026-04-06

## Контекст

Проект RepairIS — desktop-приложение для малого ремонтного предприятия.
Характеристики проекта:
- Команда: 1 разработчик
- Тип системы: Windows Forms (desktop)
- Объём данных: до 10 000 заявок
- Количество пользователей: до 100
- Требуется быстрый старт и простота развёртывания

Возможные варианты:
1. **Монолит** — единое приложение со слоями
2. **Микросервисы** — набор независимых сервисов

## Решение

Выбран **монолитный архитектурный стиль** с разделением на слои:
- UI (Windows Forms)
- Business Logic (RequestSystemFacade)
- Data Access (Adapters)
- Storage (JSON-файлы)

Реализация паттернов:
- **Facade** — единая точка входа (RequestSystemFacade)
- **Adapter** — каждый адаптер работает с одним JSON-файлом

## Последствия

### Положительные
✅ Простота разработки и развёртывания
✅ Не требует серверной инфраструктуры
✅ Быстрый старт для одного разработчика
✅ Лёгкость тестирования (xUnit, покрытие 89%)
✅ Нет накладных расходов на сетевое взаимодействие

### Отрицательные
❌ Сложнее масштабировать при росте нагрузки
❌ При переходе на клиент-сервер потребуется рефакторинг
❌ Одновременная работа нескольких пользователей ограничена
❌ Нет горизонтального масштабирования

## Альтернативы

**Микросервисы** — отклонены, потому что:
- Избыточны для 1 разработчика
- Требуют инфраструктуры (Docker, оркестрация)
- Усложняют отладку и тестирование
- Не дают преимуществ при малом объёме данных

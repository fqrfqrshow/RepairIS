# ADR-002. Выбор хранилища данных (JSON вместо СУБД)

## Статус
Принято

## Дата
2026-04-04

## Контекст

Система должна хранить данные:
- заявки (Request)
- станки (Machine)
- осмотры (Inspection)
- сметы (Estimate)
- мастера (Master)
- пользователи (User)

На этапе прототипирования:
- Не требуется многопользовательский доступ
- Не требуется транзакционность
- Не требуется репликация
- Объём данных небольшой (до 10 000 заявок)

Возможные варианты:
1. **JSON-файлы** — текстовые файлы на диске
2. **SQLite** — встраиваемая СУБД
3. **PostgreSQL / MySQL** — полноценная СУБД

## Решение

Выбрано **хранение в JSON-файлах** с библиотекой **Newtonsoft.Json**.

Каждой сущности соответствует отдельный файл:
- `orders.json` — заявки
- `machines.json` — станки
- `inspections.json` — осмотры
- `estimates.json` — сметы
- `masters.json` — мастера
- `users.json` — пользователи
- `status_history.json` — история статусов

Доступ к данным реализован через **паттерн Adapter** (OrderAdapter, RequestAdapter, InspectionAdapter, EstimateAdapter, MasterAdapter).

## Последствия

### Положительные
✅ Не требует установки и настройки СУБД
✅ Простота резервного копирования (копирование файлов)
✅ Легко читать и отлаживать данные
✅ Соответствует требованиям малого предприятия
✅ Быстрый старт проекта
✅ Файлы создаются автоматически при первом запуске

### Отрицательные
❌ Нет транзакций
❌ Нет параллельного доступа (race conditions)
❌ При росте объёма данных производительность снизится
❌ Нет индексов и оптимизации запросов
❌ При переходе на СУБД потребуется адаптация слоя доступа

## Альтернативы

**SQLite** — отклонена, потому что:
- Требует установки NuGet-пакета
- Усложняет тестирование (нужно создавать временные БД)
- Для малого объёма данных JSON достаточно

**PostgreSQL / MySQL** — отклонены, потому что:
- Требуют развёртывания сервера БД
- Избыточны для desktop-приложения
- Усложняют развёртывание на машине пользователя

## Митигация (снижение рисков)

- **Паттерн Adapter** упрощает будущий переход на СУБД — достаточно заменить реализацию адаптеров.
- **Автоматическое резервное копирование** JSON-файлов минимизирует риск потери данных.
- **Ежедневное копирование** файлов в отдельную папку.

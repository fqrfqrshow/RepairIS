## Настройка IDE

### Visual Studio 2022
1. Установлен .NET Framework 4.8 SDK.
2. Установлены рабочие нагрузки: «Разработка классических приложений .NET».
3. Подключено расширение **SonarLint** (Extensions → Manage Extensions).

### Плагины
1. **SonarLint** — статический анализ в реальном времени.
2. **ReSharper** (опционально) — рефакторинг, навигация по коду.
3. **EditorConfig for Visual Studio** — поддержка `.editorconfig`.

### Горячие клавиши
1. `Ctrl + K, Ctrl + D` — форматирование документа.
2. `Ctrl + R, Ctrl + R` — переименование.
3. `Ctrl + Shift + B` — сборка решения.
4. `F5` — запуск с отладкой.
5. `Ctrl + Alt + B` — показать панель ошибок.

### Тема оформления
1. Тёмная тема **Dark** (настройка по умолчанию).
2. Шрифт: **Consolas 11pt**.

## Конфигурационные файлы

В корне репозитория размещены:

1. `.editorconfig` — правила форматирования C#-кода.
2. `.pre-commit-config.yaml` — настройка pre-commit хуков.

## Форматтер

**Инструмент:** `dotnet format` (встроен в .NET CLI).

**Применение:** dotnet format --verify-no-changes


Команда форматирует весь код проекта по правилам `.editorconfig`.

## Линтер

**Инструмент:** SonarLint для Visual Studio.

**Настройка:**
1. Подключение локального анализатора.
2. Включены все правила по умолчанию.
3. Критичные правила: S1116 (не допускать пустые операторы), S1854 (неиспользуемые переменные), S2259 (null-проверки).

## Pre-commit

**Инструмент:** `pre-commit` (Python).

**Настройка:** см. файл `.pre-commit-config.yaml`.

**Применение:** pre-commit install

При каждом коммите запускаются хуки (форматтер + линтер). Если проверки не пройдены — коммит блокируется.

## Статический анализ

**Инструмент:** PVS-Studio (или встроенный анализатор VS).

**Применение:** анализ в фоновом режиме при открытии проекта.
